# BM25 and semantic retrieval parity

This report records how Lumen's indexing and retrieval tests cover both
retrieval modes, what the shared, source-judged case catalog measures, and where
BM25 still misses. It is regenerated by running the commands below; numbers here
are from 2026-10-11 on macOS arm64, Ollama all-minilm.

## How to reproduce

```bash
make test                       # includes the offline BM25 catalog (TestRetrievalCatalogBM25)
make eval                       # writes bin/retrieval-bm25.md (per-case report)
make e2e-bm25                   # executable BM25 suites, no embedding service
make e2e-semantic               # executable semantic suites (Ollama + all-minilm required)
make e2e-lang                   # historical semantic language snapshots
make e2e-semantic-catalog       # diagnostic: the catalog with real embeddings (slow)
```

plus contained text, optional symbol or line), never chunk identities.

### What changed BM25 results

Defects found by the catalog and fixed test-first:

- **Project identity**: symlinked project paths (macOS `/var`, linked checkouts)
  made `index`/`status` and `search` address different project rows in both
  modes; status reported 0 files and searches re-indexed.
- **Indexing loss**: YAML/JSON spans were computed from re-serialized text (JSON
  chunks collapsed to one line); Dart methods/getters/typedefs covered only
  their signature line; Rust docs over 10 lines and attributes were cut; Python
  function-local assignments became chunks; Ruby setters, JS assigned functions
  (`app.use = function`, `Reply.prototype.send`), `module.exports`, C/C++
  prototypes, function-pointer typedefs, out-of-line operators and destructors,
  and C# operators/indexers/finalizers were not extracted; `.mts/.cts/.cjs` were
  not indexed; splitting structured chunks shifted line numbers by their
  `# path:` header.
- **Structural context**: initializer calls (`const x = await f()`) were treated
  as bindings; `./x.js` did not resolve to `x.ts`; `export { x }` and default
  exports were never expanded.
- **Recovery**: a file edited or deleted after the Merkle scan aborted the BM25
  pass, and the semantic pass stored new content under the scanned hash and
  stamped partial work fresh; project lock waits ignored cancellation.
- **Extensions** (approved scope): Svelte template/style/statement regions,
  fence-aware Markdown H1–H6.
- **Ranking**: candidates are re-ranked by IDF-weighted query-term coverage
  (`coverageWeight = 0.5`). Variants with weights 0.25–1.0, weighted or not, all
  scored 396–398 supported passes; the middle, IDF-weighted setting was chosen
  rather than the single best point. It fixed nine cases and regressed three
  (`rust.matcher_borrowed_captures_at`, `lang.go.time_series_*`,
  `lang.dart.cascade_route_matching`), listed below.

### Remaining BM25 misses

`testdata/retrieval/known-misses-bm25.json` lists the 20 supported outcomes that
still fail, each classified. The list is a ratchet: tests fail on new misses and
on listed cases that start passing. No target, rank budget or category was
changed to make a case pass.

- **Vocabulary mismatch (3)**: configuration/loading vs `Config`/`Load`; logging
  vs `logger`; "boxes a formatted error" vs `Box`/`format!`.
- **Ranking (17)**: 9 broad language-suite queries where small adjacent chunks
  (one-line interface signatures, dependency entries, constants) or large
  documentation chunks outrank the answer; 8 task cases where a sibling sharing
  every distinguishing term ranks first (`try_lock_owned` vs `lock_owned`,
  `endOfRunStaleness` vs `run`, interface/fake vs Stripe implementation,
  unqualified Java method symbols).
- **No indexing loss remains** among supported cases.

Diagnostic outcomes stay in every report: 10 natural-language vocabulary probes
(3 hit), CJK substring search (unsegmented), `operator==` vs `operator!=`
(punctuation is not tokenized), terms beyond the 64-term cut, and original
queries with no valid answer in their corpus (for example Go "authentication
token validation" over Prometheus).

## Historical snapshot comparisons

`TestLang_*` (semantic, all-minilm) still compare the unchanged historical
snapshots. `TestLang_BM25SnapshotDiagnostics` replays them against BM25: 2 of 58
match, which measures chunk-identity differences (BM25 keeps whole symbols;
semantic splits and merges), not relevance. Relevance for those 58 queries is
judged by the `lang.*` catalog cases instead.

Semantic snapshot status with all-minilm on the local Ollama runtime
(`make e2e-lang`):

| code                                          | snapshots matching |
| --------------------------------------------- | ------------------ |
| handoff (`98dfa40`, mode explicitly semantic) | 48/58              |
| after this change                             | 33/58              |

The 10 handoff mismatches are local runtime/model drift (CI pins its Ollama
image). The 15 additional mismatches are all in languages whose extraction
changed (Dart method bodies, JS assigned functions, JSON spans, Python local
assignments, Rust docs, TS, YAML). For example, Dart `response body status code`
returns the same `response.dart` spans, now named `Response.ok` and
`Response.seeOther` (function) instead of the enclosing `Response` (type). The
snapshots were deliberately **not** regenerated: refreshing them is a reviewed
step on the pinned CI runtime (`UPDATE_SNAPSHOTS=1 make e2e-lang`), not
something to do against a drifting local model.

## Cost

`BenchmarkRetrieval` on the five-file smoke corpus (Apple M-series): direct
queries 336 µs/op and expanded queries 651 µs/op, up from roughly 157 µs and 206
µs before coverage re-ranking, which adds one IDF lookup and hydrates up to 30
candidates. Related context remains bounded at two snippets and 6000 bytes.
