Research 18/25 — Typed retrieval plans, databases, and visual documents

Recommendation: build a small cost-aware query planner over existing retrieval channels, rather than choosing one universal embedding. This is a practical transfer from database optimizers. Treat it as an integration hypothesis, not a new algorithm proved by the cited papers.

Primary sources verified:
1. Selinger et al., “Access Path Selection in a Relational Database Management System” (SIGMOD, 30 May 1979), https://doi.org/10.1145/582095.582099 . System R separates declarative predicates from physical access paths and chooses access paths/join order to minimize estimated execution cost. Transfer: record selectivity/cardinality, compute cost, and available indexes; choose among lexical lookup, semantic candidates, graph expansion, and filters instead of always executing everything.
2. Patel et al., “Semantic Operators: A Declarative Model for Rich, AI-based Analytics Over Text Data” (initial July 2024; verified v2, 18 November 2024), https://arxiv.org/html/2407.11418v2 . LOTUS composes semantic filters, joins, ranking, grouping and aggregation with relational operations. Proxy models/embeddings plus sampled thresholds avoid evaluating every item with a large model. Its headline up-to-400x applies to particular bulk operators against naive evaluation, not general agent search. Crucial limitation: statistical accuracy is relative to the expensive reference model, not guaranteed factual truth. Paper explicitly distinguishes semantic-similarity joins from arbitrary semantic predicates.
3. Faysse et al., “ColPali: Efficient Document Retrieval with Vision Language Models” (initial June 2024; ICLR 2025), https://arxiv.org/html/2407.01449v4 . Page-image multi-vector representations and late interaction preserve tables, figures and layout. ViDoRe table 2 reports mean nDCG@5 81.3 versus 67.0 for its captioning+BGE-M3 baseline. This is that benchmark, not evidence for code or all PDFs. Storage is 257.5 KB/page in float16; preprocessing savings were measured against an elaborate OCR/layout/captioning pipeline on an NVIDIA L4. Therefore this should be an optional visual-document route, not the default local index.

Minimal proposed design:
• Represent a query as typed predicates plus ranked preferences: literal/symbol, semantic intent, relation, numeric range+unit, timestamp, negation, modality. Keep uncertain interpretations explicit.
• Store source spans/page coordinates alongside typed fields, confidence, content hashes, and provenance. Numeric/time fields get exact evaluators; joins and graph reachability use explicit edges. Extracted facts remain uncertain until checked against source.
• Use document frequency/cardinality and measured per-operator latency to choose a plan. Selective exact filters can precede semantic ranking. Compare prefiltered search against oversampled candidates plus postfiltering; avoid assuming one order is always fastest. Retrieval-score thresholds are not truth predicates.
• Separate discovery (“which files discuss disabling retries?”) from verification (“does this implementation never retry?”). Negation in natural-language text needs evidence/entailment, not merely absence of a keyword. Answering “all,” counts, and absence requires a complete-scope scan or a stated incomplete result; top-k cannot certify completeness.
• Produce compact evidence bundles with original spans, satisfied constraints, uncertainty, and an available continuation. Request visual pages only for layout-sensitive questions; extract exact table cells after discovery.

Falsifiable evaluation: stratify 300 held-out queries across literals, paraphrases, joins, numeric/time constraints, negation and visual pages. Compare rg, lexical-only, vector-only, fixed hybrid, and typed planner with identical context budgets. Measure task success, hard-constraint violation rate, evidence recall, bytes/tokens returned, p50/p95 latency, index/storage/build cost and amortized cost over query volume. Ablate typed filters and planner independently. Reject this design unless it reduces hard-constraint violations and total agent cost at matched task success; include planner/model overhead and stale-index tests. No implementation or local benchmark was performed here.
