R14/25 — Index-performance engineering; verified 2026-10-11

Recommendation: retain exact lexical retrieval for identifiers and small collections; adopt learned sparse or dense representations only for a measured relevance gain. Choose Seismic/HNSW after measuring the representation, query encoding, cold-start and agent-loop costs. None of the papers establishes a small-repository crossover or superiority over ripgrep on agent task completion.

Primary evidence

1. Bruch et al., “Efficient Inverted Indexes for Approximate Retrieval over Learned Sparse Representations,” 2024-04-29 / SIGIR 2024. https://arxiv.org/html/2404.18812v1 . Seismic combines truncated inverted lists, geometrically coherent blocks, approximate summary vectors and forward-vector rescoring. Unlike exact WAND/MaxScore pruning, approximation can miss documents. Its benchmark explicitly excludes embedding time and measures single-thread query-vector-to-results latency. MS MARCO/SPLADE index: 6,416 MiB, five-minute construction using 64 hardware threads; PyAnn: 5,262 MiB, 137 minutes; GrassRMA: 10,489 MiB, 267 minutes. Thus fast query execution does not mean free memory or indexing. Learned sparse vector distributions differ from lexical BM25; these speedups do not establish Seismic as a BM25 replacement. Core novelty applicable here: geometrically coherent blocks plus cheap block summaries, provided approximate recall is acceptable.

2. Malkov/Yashunin, “Efficient and robust approximate nearest neighbor search using Hierarchical Navigable Small World graphs,” submitted 2016-03-30. https://arxiv.org/abs/1603.09320 . Incrementally builds a hierarchical proximity graph. Useful when semantic vectors are already justified; it searches embeddings, not text meaning independently. Index choice cannot rescue a representation that fails on identifiers. Incremental construction does not by itself verify deletion-heavy or repository-branch-switch correctness.

3. Patel et al., “ACORN: Performant and Predicate-Agnostic Search Over Vector Embeddings and Structured Data,” 2024-03-07 / SIGMOD 2024. https://arxiv.org/html/2403.04871v1 . Filtered ANN must account for correlation between metadata predicates and vector neighborhoods, not only the fraction of documents allowed. The paper uses predicate-subgraph traversal and explicitly falls back to exact prefiltered search for sufficiently selective predicates. ACORN-1 trades some query throughput for 9–53× lower construction time than ACORN-gamma in its experiments. Relevant transfer: path/language/branch constraints should inform retrieval planning; blindly oversampling global ANN then filtering can fail. Its million-vector experiments are not local-repo benchmarks.

Cost model (our inference, not empirical results)

For Q queries before rebuild: index amortization wins only when Q > (build + update + cold-load overhead)/(scan-per-query − indexed-per-query), assuming positive denominator and equal utility. Include embedding generation in build and query encoding in indexed query cost. Example assumptions: 30-second build and 20ms versus 2ms queries require >1,667 queries; a changed document set can reset the calculation. Cached reusable indexes reduce this overhead.

Agent time = initialization + sum(query encoding + search + reranking + tool/LLM round trips + context processing). Hypothetically improving 20ms search to 1ms saves 19ms, while eliminating one multi-second agent round trip saves seconds. Optimize useful evidence per returned token and calls-to-solution before index microseconds.

Benchmark required: 1k/10k/100k chunks; warm daemon, fresh process and cold filesystem; 1/10/100/1000 queries per checkout; edits, deletions and branch switches; filters retaining 0.1/1/10/100%; exact identifiers versus paraphrases. Compare rg, exact BM25, flat vector scan, HNSW, and Seismic at matched evidence recall. Record indexing/encoding cost, RSS, p50/p95, stale-hit rate, token volume, agent turns and task success. No local crossover has been measured by this subagent.
