# R10 — Graph retrieval / compiler-analysis research

Recommendation: retain lexical search as the seed generator and add optional, bounded, typed multi-hop retrieval. Extend Lumen's existing conservative one-hop function calls; do not replace them with an LLM-generated knowledge graph. This is a testable research proposal, not a verified Lumen speedup.

## Verified primary evidence (checked 2026-10-11)

1. Chen et al., LocAgent (March 12, 2025; inspected v2 April 29; ACL 2025), https://arxiv.org/html/2503.09089v2 . Python AST-derived nodes represent directories/files/classes/functions; edges include containment, imports, invocations, inheritance. Search combines exact entity lookup and BM25; traversal supports direction, hop count, relation and entity types. The strongest relevant evidence is the controlled Table 6 ablation with fine-tuned Qwen-2.5-7B: function Acc@10 is 71.53 full, 66.79 with one-hop-only traversal, 66.06 without traversal, and 60.22 without the BM25 index. Thus multi-hop adds 4.74 percentage points beyond one hop, while good initial search remains essential. Reported ~86% cost savings compare different LMs and cannot be attributed to graphs alone. Python benchmark results do not establish gains for Go or Lumen.

2. Gutierrez et al., HippoRAG (May 2024; NeurIPS 2024), https://arxiv.org/html/2405.14831v2 . LLM-extracted entity triples plus synonym links support query-seeded Personalized PageRank (PPR). Table 5 average passage R@5: 72.9 full PPR, 59.2 query nodes plus immediate neighbors, 56.2 query nodes only; removing specificity gives 70.9 and removing synonym links gives 70.5. These results support diffusion and degree/specificity control over indiscriminate neighborhood expansion. Authors report online retrieval 6–13x faster and 10–30x cheaper than iterative IRCoT; these exclude the indexing tradeoff and are not comparisons against rg or BM25. On HotpotQA, all-supporting-passages AR@5 is 57.9 versus ColBERTv2's 59.0: graphs are not universally better.

3. Edge et al., GraphRAG (April 24, 2024; v2 February 19, 2025), https://arxiv.org/abs/2404.16130 . LLM entity graphs, community summaries, then query-time partial-answer aggregation improve comprehensiveness/diversity for global sensemaking over million-token corpora. This is evidence for a separate document-overview mode, not for pinpointing an implementation or minimizing repository context. Global summary quality should not be treated as localization recall. Its extraction and summary maintenance are especially unattractive for frequently edited source code.

## Proposed extension, explicitly hypotheses

Build verified forward/reverse adjacency for existing resolved calls, then add imports, containment and language-resolved inheritance/implementation links where available. Distinguish confidence/provenance: statically resolved edges, naming heuristics and observed test coverage must not share one certainty level. Reverse calls connect a utility to affected callers; forward calls connect a failing public API/test to implementation. Do not call this a complete program slice: dynamic dispatch and dataflow remain incomplete.

For symptom/cross-file queries, or when held-out calibration predicts enough benefit within budget, seed from 5–10 diverse lexical/semantic hits, including error strings, public APIs and tests. Do not gate using uncalibrated top lexical score alone. Compare type-filtered two-hop BFS against approximate PPR with relation weights, restart, degree normalization and a strict expansion cap. Example experimental caps: 200 visited nodes, 20 emitted entities, and 1,500 added tokens; tune rather than assert these are optimal. Prefer paths joining two independently supported seeds. Emit the path and original source spans so an agent can inspect why a candidate surfaced. Names in tests, docs and errors provide vocabulary bridges; absent seeds/edges cannot be repaired by diffusion.

Negative cases: ubiquitous helpers become hubs; reverse traversal explodes; structural relevance differs from bug causality; reflection, generated code and stale indexes lose edges. An exact symbol query should bypass graph expansion. Graph-only ranking can bury the initial correct match, so preserve primary lexical candidates.

## Decisive ablation

Compare current Lumen, reverse edges only, typed two-hop BFS, bounded PPR, and each without tests/docs seeds. Hold reranker, model, output-token and time budgets constant. Split exact-symbol, vague symptom, cross-file cause and global-summary queries; use timestamp-correct repository snapshots. Measure supporting-function all-recall at fixed tokens, irrelevant-context fraction, end-to-end tool calls, p50/p95 latency, indexing/update time and final task success. Ship only if paired confidence intervals demonstrate benefit on vague/cross-file tasks without meaningful exact-query regression. Literature establishes plausibility; this experiment must establish product value.
