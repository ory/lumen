R09 — Hierarchical/multiscale retrieval. Literature checked 2026-10-11.

Recommendation: add source-grounded parent/child expansion and multi-resolution candidate retrieval before implementing a recursively generated summary tree. Preserve global leaf retrieval; use structure to select and pack context, not as a mandatory top-down gate. Confidence: high about the failure mode, moderate about expected Lumen gains; no repository benchmark has validated this proposal.

Primary evidence
1. RAPTOR, Sarthi et al., ICLR 2024 / arXiv 2024-01-31: https://arxiv.org/html/2401.18059v1 . Recursively clusters and summarizes chunks, retaining summaries and originals at several scales. In its controlled QASPER comparison, GPT-4 + RAPTOR reaches 55.7 F1, 2.7 points above DPR and 5.5 above BM25. Its own small querying ablation favors retrieving across all levels (“collapsed tree”) over top-down traversal; thus its headline accuracy does not prove logarithmic search speed. A clustering-vs-contiguous-tree ablation is only 56.6% vs 55.8% QuALITY accuracy. Build-time/token scaling was empirical on documents up to ~80k tokens, not a proof for arbitrary repositories. About 4% of an inspected summary sample had minor hallucinations. This is evidence for useful abstractions on long-document QA, not demonstrated code-search superiority.

2. Recursive Abstractive Processing for Retrieval in Dynamic Datasets, Chucri et al., arXiv initially 2024-10-02: https://arxiv.org/html/2410.01736v1 . adRAP incrementally adjusts clustering and regenerates affected ancestor summaries instead of rebuilding everything. Authors explicitly acknowledge extra stored UMAP/GMM models, maintenance complexity, and possible full reconstruction after large additions. postQFRAP moves query-focused summarization after retrieval, avoiding persistent summary maintenance but requiring multiple inference calls and making source tracing harder. Some evaluation questions are generated from RAPTOR nodes, creating an alignment caveat. Neither variant is an obvious fit for subsecond agent search over rapidly edited source.

3. Semantic Compression Trees, Farooq, arXiv preprint 2026-08-21: https://arxiv.org/html/2608.21610v1 . Small study: 50 QASPER papers, 173 questions. When the correct document is supplied, extractive residuals achieve 0.274 vs dense retrieval 0.277 answer F1 with ~30% fewer context tokens. Yet flat retrieval of the same residuals performs essentially identically. When document selection is required, tree descent falls to 0.122 vs 0.165 F1; document routing is 20.2% vs 39.3%. Treat as preliminary corroboration: compressing roots before choosing the document can remove the very detail needed for correct routing. Reported residual-vs-summary gains are confounded by differing context volume.

Minimal Lumen extension (engineering hypothesis)
Given existing symbol and Markdown heading extraction, store parent_id, source byte/line range, content_hash, and node kind. Hierarchies: file→type/function→block for code; document→heading→paragraph for prose. Index leaf text plus bounded ancestor titles/signatures/docstrings as separate fields. Retrieve globally across leaves and optional coarse nodes; fuse candidates; expand each winning leaf only to the smallest source parent that supplies missing definitions or adjacent explanatory prose. Deduplicate overlapping spans and obey a hard token budget. Return original text, paths, lines, and revision/hash. Any later generated overview is a navigation hint linked to descendants, never source evidence. Hash-based ancestor invalidation prevents stale summaries from silently surviving edits.

Cross-domain idea: multiresolution signal coding suggests storing only additional information at each resolution (residuals), avoiding repeated ancestor boilerplate. Apply first as deterministic span/metadata deduplication, not semantic subtraction that could erase code details.

Verification: paired benchmark under equal returned-token and total-latency budgets: (A) current flat retrieval, (B) title/signature enrichment, (C) B + bounded parent expansion, (D) C + generated summaries, (E) mandatory top-down routing. Stratify exact identifiers, paraphrased behavior, local explanation, cross-file dependencies, whole-document themes, and edits/deletions. Measure evidence recall, task completion, useful tokens/total tokens, agent tool rounds, P50/P95 wall time, build/update cost, stale-source rate. Include both known-document and unknown-document questions to expose routing failures. Prefer B/C unless D wins after amortized indexing cost.

Not useful: literal/regex lookup; tiny repositories where scanning wins; weak document structure; highly volatile corpora; global relations crossing unrelated branches without cross-links. Thematic summaries may help stable long prose more than mutable code.
