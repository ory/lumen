R05 — Late interaction: best as an optional semantic recall channel
Research checked 2026-10-11. Four primary papers; literature verification, not a local implementation benchmark.

Recommendation (inference): Retain Lumen's fielded BM25 and exact-symbol lookup. Pilot an independent compressed multi-vector index over the same AST/document chunks, union its candidates with lexical candidates, then select evidence under a fixed context budget. WARP is the most directly supported CPU-serving experiment here. MUVERA is a promising alternative when reusing a standard ANN index matters; do not implement both initially. A reranker-only pilot can cheaply test scoring quality but cannot establish the main claim: recovering relevant chunks absent from BM25's candidate set.

Why this family: a single pooled document vector can obscure a small but crucial facet. Late interaction preserves token vectors and scores each query token against its strongest contextual document-token match (MaxSim). This permits semantic alignment without requiring exact character overlap. It does not provide logical entailment, correct negation handling, or guaranteed identifier sensitivity; those need measurements. General prose benchmarks do not prove code-retrieval or agent task gains.

Verified evidence:

1. ColBERTv2 (NAACL, July 2022): residual compression stores a centroid ID plus quantized residual. A 128-dimensional token vector uses 20 bytes at 1 bit/dimension or 36 bytes at 2 bits, versus 256-byte float16 vectors in original ColBERT. These are vector encodings, not total index cost. The paper reports 6–10× smaller late-interaction indexes with improved retrieval quality through compression plus denoised training. This is compression relative to older multi-vector retrieval, not relative to BM25 or single-vector indexes. For a hypothetical 100k chunks averaging 150 indexed tokens, 36 bytes/token alone implies 540 MB before metadata, postings and model weights (arithmetic estimate). https://arxiv.org/html/2112.01488

2. PLAID (CIKM 2022): centroid-level approximate scoring/pruning avoids expensive full-token scoring for most passages. Its MS MARCO table reports ColBERTv2/PLAID k=100 MRR@10=39.8, Recall@100=90.6, with 222.3 ms on one CPU thread, 52.9 ms on eight, and 20.2 ms on GPU. Crucial qualification: neural query-encoding latency is excluded. Hardware is Xeon Gold 6132 and TITAN V; borrowed BM25/SPLADE latency figures use different implementations/hardware and cannot establish fair end-to-end superiority. This is an engine optimization over a learned representation, not a universal relevance improvement. https://arxiv.org/html/2205.09707

3. WARP (SIGIR 2025; arXiv v3, July 2025): XTR-trained token retrieval plus missing-score imputation, implicit decompression and optimized aggregation reduces unnecessary gather/scoring work. On LoTTE Pooled test, XTR-base/WARP achieves Success@5 69.3 and mean 171.3 ms, versus optimized XTR-base/ScaNN 68.4 and 2156.3 ms. The advertised 41× is against the slower reference baseline, not that optimized comparison. Measurements use one CPU thread on Xeon Gold 6132 servers with 500 GB RAM and report the minimum mean over three trials; these are not laptop p95 numbers. For 660M tokens, WARP indexes are 23.88 GiB at 2 bits and 43.59 GiB at 4 bits versus ScaNN's 87.30 GiB; PLAID is approximately the same size as WARP. WARP's 2–4× footprint reduction is therefore against XTR/ScaNN, not PLAID. https://arxiv.org/html/2501.17788v3

4. MUVERA (NeurIPS 2024): randomized geometric encodings map a document's token-vector set to one fixed-dimensional encoding, enabling standard maximum-inner-product ANN search followed by true multi-vector reranking. This transfers geometric sketching ideas into retrieval. A 10,240-dimensional encoding compresses to 1,280 bytes with PQ, but original document token vectors for reranking and the ANN graph remain additional storage. Experiments use single-thread latency on Sapphire Rapids c3-standard-176; throughput uses 176 threads. Its MS MARCO result of 95% recall with 75 candidates and 5,120 dimensions refers specifically to recovering the exact Chamfer top-1 neighbor, not human relevance recall. The paper's separate relevance evaluations do not prove an advantage on Lumen code. https://papers.neurips.cc/paper_files/paper/2024/file/b71cfefae46909178603b5bc6c11d3ae-Paper-Conference.pdf

Falsifiable minimum experiment: freeze 200+ independently judged repository queries stratified into exact identifiers, vague task descriptions, semantic paraphrases, typo/abbreviation and multi-facet requirements. Compare (A) existing BM25+one-hop, (B) A+single-vector recall, (C) A with late-interaction reranking only, (D) independent multi-vector recall union+rereanking. Keep identical chunk boundaries, context budgets and candidate caps. Measure missing-gold rescue at candidate stage, evidence Recall@20, successful agent tasks, returned tokens, cold/warm p50/p95 including query encoding, index bytes, build time and edit-to-search freshness. Pre-register local adoption thresholds: at least +5 percentage points vague-query evidence recall with no >1-point exact-query regression, and lower median total task cost including amortized indexing. Reject the added dependency if these are unmet. Thresholds are proposed engineering gates, not literature findings.
