Research 15/25 — Evidence compression. Primary sources verified 2026-10-11.

Recommendation: add a provenance-preserving, hard-budget evidence packer before adopting learned token deletion. Return complete source spans, selected for marginal usefulness and coverage, with progressive expansion handles. This is an engineering inference supported by the following research, not a published algorithm or verified Lumen speedup.

1. Pan et al., LLMLingua-2 (Findings ACL, August 2024): https://aclanthology.org/2024.findings-acl.57/ . A bidirectional encoder classifies which tokens to retain, trained on distilled compression examples. Authors report 2–5× compression and 1.6–2.9× end-to-end acceleration in their experiments. This establishes that compression can pay for its own compute, but does not establish syntax/semantic preservation for code. Distinguish their token deletion from whole-span extraction; token copying alone cannot guarantee that removing a negation, scope delimiter, identifier, or condition preserves meaning. Experiment with this later on prose-only previews; retain accessible originals.

2. Xu, Shi, Choi, RECOMP (ICLR 2024): https://proceedings.iclr.cc/paper_files/paper/2024/file/bda88ed2892f5e61c9a9bf215c566913-Paper-Conference.pdf . Separates extractive sentence ranking from abstractive multi-document summaries, trained for downstream LM usefulness, and allows empty output for unhelpful evidence. QA results report 5–10% retained tokens with under 10% relative performance loss and approximately 2× inference acceleration. Caution: its small manual audit (30 non-empty summaries) finds only 67% of its HotpotQA summaries fully faithful; 40% both faithful and comprehensive. Thus generated summaries should help navigation, never replace authoritative source evidence. Even extraction can mislead when qualifiers or antecedents are omitted.

3. Liu et al., Lost in the Middle (TACL, February 2024): https://aclanthology.org/2024.tacl-1.9/ . Controlled multi-document QA and key-value tasks show strong position sensitivity, often favoring beginning/end. In tested older readers, retrieval recall keeps improving after answer accuracy saturates. This motivates budgeted selection and relevance ordering; it is not evidence that every contemporary model has the same curve. Retest on the actual agent model.

Lumen design proposal: retrieve a generous internal candidate set; deduplicate overlapping ranges; select complete functions/definitions or coherent paragraph spans under a shared payload budget. Preserve file path, revision/content hash, line range, reason for inclusion, and a stable expansion handle. Large spans yield signature plus explicit omitted-region marker and fetch handle, never quietly mutilated code. Count tokens after final serialization, including JSON escaping, wrappers, metadata, and any duplicated text/structured representations. Apply a conservative byte ceiling too, because transport limits differ from model limits. Return truncation status and remaining-result count. This directly addresses the parent-reported 763k-character rejected tool output; that incident was not independently audited here.

Ablation: same retrieved candidates, compare top-k fixed windows, whole-span budget packing, learned token deletion, and generated summaries. Sweep 2k/4k/8k serialized-token budgets; measure answer/patch success, evidence coverage, citation correctness, p50/p95 latency, compressor cost, retries, and total session tokens—not compression ratio alone. Include negation, similarly named symbols, cross-file dependencies, contradictory docs, giant functions, and multi-hop questions. Test progressive disclosure with the cost of extra round trips included. Ship deterministic packing first if it improves cost at non-inferior task success; require confidence intervals rather than a single benchmark mean.
