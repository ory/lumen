Research 07/25 — query formulation, verified 2026-10-11

Recommendation: expose a batch search interface accepting original query, immutable exact terms, and at most two short alternate formulations produced by the agent already making the tool call. Search variants independently, fuse ranked candidates, and reserve part of the context budget for original-query/exact hits. On failure, permit one corpus-grounded reformulation. This is a proposed engineering adaptation, not a published algorithm or measured Lumen result.

Primary evidence (three papers)

1. Query2doc (EMNLP, December 2023): https://aclanthology.org/2023.emnlp-main.585.pdf . Generates a pseudo-document, appends it to the query, and repeats original query terms five times for sparse retrieval. Crucial ablation: TREC DL19/20 nDCG@10 was 66.2/62.9 with combined query, 51.2/47.7 with original only, and 48.7/44.5 with pseudo-document only. Thus generated text should not replace the original. Costs in that historical experiment: >2,000 ms generation; index search 177 ms versus 16 ms BM25 (single thread, top 100 MS-MARCO). These are not contemporary latency predictions. The paper documents false generated details; self-revision did not consistently improve results. It evaluates passage retrieval, not repository code. Its main lesson for Lumen is useful lexical expansion with strong original-intent retention, coupled with explicit expansion-length limits.

2. HyDE (preprint December 20, 2022; ACL 2023): https://aclanthology.org/2023.acl-long.99.pdf . Generates hypothetical relevant documents, embeds them with an unsupervised contrastive encoder, then retrieves actual documents by similarity. It addresses missing relevance labels and vocabulary mismatch. The proposed dense bottleneck can suppress incorrect generated details; this does not establish hallucination immunity. Lumen’s default BM25 profile does not create a dense index (optional semantic mode exists), so genuine HyDE is not a drop-in BM25 change; pseudo-code sent into BM25 is a different method. A false invented symbol is particularly dangerous in code because symbol identity may determine correctness. Defer HyDE until a dense-index ablation shows benefit beyond lexical expansion.

3. ThinkQE (arXiv v1 June 10, 2025): https://arxiv.org/html/2506.09260v1 . Uses initial BM25 results, reasoning-based expansion, successive retrieval feedback, and filtering of previously seen documents. Three rounds, two sampled expansions each, top-five feedback documents. Reported BRIGHT StackExchange mean nDCG@10: 34.9 versus BM25 17.0 and BM25+GPT-4o reasoning rewrite 33.9. Importantly, authors explicitly exclude BRIGHT code and mathematics because natural-language expansions may be unsuitable there. The paper acknowledges higher latency and compute. Feedback rounds beat static parallel expansion in its experiments, but this is evidence for selective deeper search on hard document queries, not universal use in a low-latency code tool.

Proposed implementation constraints

Reuse the agent's explicit tool arguments rather than launching a hidden model within every search. This removes an extra inference call, not the token cost of producing variants. Preserve paths, quoted strings, error codes, and case-sensitive identifiers separately; alternate semantic descriptions can broaden search. Abstract/step-back variants suit conceptual questions; decomposed variants suit cross-file questions. Both can drift away from the requested entity. Weighted reciprocal rank fusion preserves independently retrieved exact candidates better than mixing all expansion terms into one long query, but fusion alone does not guarantee their survival: reserve slots and measure regression. Do not index generated answers as facts.

Concrete experiment

On held-out code/doc questions stratified into exact-symbol, error-string, paraphrase, conceptual and multi-file classes, compare baseline; one concatenated expansion; original plus two fused variants; and the latter plus one feedback round. Evaluate relevant-symbol recall at a fixed 2k/4k-token budget, irrelevant tokens, task success, p50/p95 wall time, total model tokens, search calls and exact-query regressions. Use identical agent/model budgets; freeze queries before scoring; report bootstrap intervals. Proposed gate: adopt only if paraphrase recall improves materially without exact-hit loss and end-to-end cost falls or remains acceptable. Never infer production wins from passage benchmarks alone.
