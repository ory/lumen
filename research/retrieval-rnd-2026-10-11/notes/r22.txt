Research 22/25 — Evaluation protocol (2026-10-11; primary papers accessed today)

Current evidence: r02 finds five smoke queries, biased task selection, inactive retrieval arms, discarded test outcomes, unblinded judging, and excluded indexing costs. None supports superiority to a competent rg-equipped agent. Repair instrumentation before spending on comparisons.

External anchors
• ContextBench (v3, 2026-02-11) annotates 1,136 tasks across 66 repositories, aligning inspected and declared context at file/block/line granularity. It validates sufficiency through test-passing patches and expert review, but deliberately selects difficult tasks. Use its process instrumentation, not its distribution as a universal workload. https://arxiv.org/html/2602.05892v3
• SWE-Explore (v1, 2026-06-05) returns ranked regions under line budgets. Its 848 instances require at least two successful trajectories; intersected reads plus refinement provide evidence, not exhaustive necessary context. The paper explicitly acknowledges alternative valid evidence and selection toward solvable issues. https://arxiv.org/html/2606.07297v1
• Agent Retrieval Bench (v1, 2026-07-27) separates 345 positive cases, 50 evidence-backed natural no-gold cases, and 32 wrong-repository controls. Threshold benefits on mixed negatives disappear on natural cases. Its authors explicitly deny exhaustive labels and distinguish a path-aware lexical heuristic from standard BM25. https://arxiv.org/html/2607.24882v1

Proposed preregistered protocol
1. Freeze 240 positive tasks from 24 repositories, stratified across exact identifiers, behavioral paraphrases, cross-file diagnosis, dependency tracing, and documentation questions; add 60 natural no-answer cases and 30 synthetic/wrong-repository controls. These counts define a feasible initial study, not guaranteed statistical power: estimate detectable effects from a separate pilot. Preserve realistic exact queries; report mismatch strata separately instead of filtering out rg-friendly tasks. Balance repositories; freeze source manifests and pre-fix commits.

2. Independently annotate three objects: relevant filenames; supporting line intervals; alternative sufficient evidence sets (e.g., caller AND implementation AND configuration, with documented substitutes). Include unchanged code, tests, and documentation. Report file Recall@k/MRR, deduplicated line recall, and complete-evidence-set success at 2k/4k/8k delivered tokens. File hits cannot substitute for evidence coverage. Two reviewers adjudicate pooled outputs from all methods blind to identity. Mark unjudged material unknown; publish label coverage and sensitivity analyses rather than calling every non-gold line noise.

3. Run identical-model, identical-prompt arms: competent agent with rg/path search/regex/query decomposition and reads; plus Lumen BM25; plus BM25 with bounded relations; plus semantic fallback. Keep common tools, instructions, permissions, time/output caps, and source access fixed. Separately run static retrieval and a restricted-context repair experiment with identical solver, random-context and oracle-context controls; this tests context value without conflating it with agent policy. Verify final serialized payload caps.

4. Log every attempted call, accepted response, read interval, truncation, failure, and declared final evidence. Report tool-adoption rate and intention-to-treat success; do not discard Lumen non-use. Primary repair endpoint: hidden regression tests demonstrably fail on base and pass on gold, alongside existing-test preservation. Preserve exit statuses. Use blinded human/judge ratings only as secondary evidence; for document answers score factual correctness and citation entailment against expert rubrics.

5. Split tuning/test by repository; group forks, near-duplicate issues, paraphrases and adjacent snapshots. Add a forward-time holdout collected after configuration freeze. Remove fix artifacts from agent access. Public-task memorization remains possible; distinguish recent/private prospective evaluation from merely holding out public tasks. Calibrate abstention on held-out natural negatives; publish natural and counterfactual results separately, including false abstentions on positives.

6. Report cold setup, indexing/embedding, updates, startup, retrieval, agent/test latency, storage, API/cache charges and failures. Total per-task cost/time includes lifecycle overhead amortized across explicit N=1/10/100 task scenarios, with cache state declared.

7. Use three randomized-order paired runs per task; report every run, not best-of-three. Publish paired differences with repository-cluster bootstrap 95% intervals, resampling tasks/repeats within repository while preserving arm pairing. Report repository-macro and task-weighted effects, language/task strata, median/p95 latency, and preregistered primary endpoint. Claim improvement only when practical gain and uncertainty support it.
